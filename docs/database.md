# Database

DataVault uses PostgreSQL and Drizzle ORM. UUID primary keys are generated by PostgreSQL. Important monetary columns use `NUMERIC(18,2)`; JavaScript floating point is not used for authoritative calculations.

## Table groups

- Identity: `users`, `accounts`, `sessions`, `verifications`
- Tenancy/RBAC: `organizations`, `organization_members`, `roles`, `permissions`, `role_permissions`, `user_roles`, `organization_invitations`, `saved_views`
- Universal records: `saved_records`, `capture_sources`, `attachments`
- Docs: `notes`, `note_revisions`, `user_note_prefs`
- Financial domain: `payments`, `refunds`, `customers`, `vendors`, `categories`, `payment_methods`, `invoices`, `invoice_items`, `invoice_payments`, `recurring_payments`
- Operations: `audit_logs`, `extension_auth_codes`, `extension_sessions`, `extension_refresh_tokens`, `idempotency_keys`, `rate_limit_buckets`

`saved_records` is the durable universal layer. A browser capture can remain a note/other record even when it cannot be fully classified. `payments`, `invoices`, customers, vendors, refunds, and recurring schedules reference their corresponding saved record.

`notes` holds a doc. Its content is the rich text the editor works with, stored as JSON, with the plain text kept beside it for search and summaries. A doc carries a version number, so two people cannot overwrite each other, and a clip count and the time of the last piece.

`note_revisions` keeps the earlier versions of a doc. Only the last thirty versions of each doc are kept, and a version is only stored every ten minutes while the user is typing.

`user_note_prefs` holds the doc a person is currently adding to. It is one row per person per workspace, so the website and the browser extension always agree on the same doc.

## Constraints and indexes

- Non-negative money and positive refund constraints are enforced in SQL.
- Payment/invoice party constraints prevent ambiguous ownership.
- Organization-scoped identifiers and saved-record links are unique.
- Organization/date/status/reference indexes support common lists.
- PostgreSQL trigram indexes cover titles, original captured text, and party names.
- `pg_trgm` and `unaccent` are enabled by the first migration.

## RLS

Tenant tables have a `tenant_isolation` policy comparing `organization_id` with `current_setting('app.organization_id', true)`. API service transactions call `set_config(..., true)` before business queries. Local setup may use a PostgreSQL superuser for convenience, but production must use a least-privilege login that does not bypass RLS.

## Migrations and seed

```bash
bun run db:generate
bun run db:migrate
bun run db:bootstrap
bun run db:remove-demo
bun run db:check
```

Review generated SQL before production deployment. `db:bootstrap` only ensures the global permission catalog exists. `db:remove-demo` removes the former local demo accounts and their two known demo workspaces while preserving other users and data.
